1. PROJECT OVERVIEW
--------------------------------------------------------------------------------
SympoHub is a full-stack web platform that centralizes college events in one
place. Students can discover symposiums, workshops, hackathons, paper
presentations, project expos, cultural fests and sports meets, register in
seconds, track My Events, manage their profile, and collect participation
certificates.

Tagline: "Discover Your Next College Event. Symposiums, workshops,
hackathons and more."

Key Value Propositions:
  - Single hub for events from multiple colleges (Anna University, PSG Tech,
    SSN, VIT Chennai, SRM Institute, NIT Trichy, Loyola College, etc.)
  - Fast search + category / college / date / type filters + sorting
  - One-click registration with seat tracking and duplicate protection
  - My Events dashboard with Registered / Upcoming / Completed status
  - Auto-generated Participation certificates for completed events
  - Secure JWT authentication with persistent login
  - Modern responsive UI with glassmorphism, animations, skeletons

    name required, email required unique lowercase trim regex /^\S+@\S+\.\S+$/,
    phone required, college required, department required,
    passwordHash required, createdAt. No passwordHash in public responses.
  Registration (models/Registration.js):
    studentId ObjectId->Student required, eventId ObjectId->Event
    required, registrationDate default now, status enum[Registered,
    Upcoming, Completed] default Registered. Unique (studentId,eventId).
  Certificate (models/Certificate.js):
    studentId->Student, eventId->Event, certificateType default
    Participation, certificateUrl default '', issuedDate default now.

8. BACKEND - API REFERENCE
--------------------------------------------------------------------------------
Base URL: http://localhost:5000/api (frontend VITE_API_URL)

  Students (/api/students):
    POST /register
      Body: {name, email, phone(10 digits), college, department|dept,
      password(min6)} -> 201 {student:{id,name,email,phone,college,
      department,createdAt}, token(7d)} | 400 validation | 409 email exists
    POST /login
      Body: {email,password} -> 200 {student,token} | 401 invalid
    GET /:id
      Param MongoId -> 200 {student(-passwordHash)} | 404
    PUT /:id (Auth: Bearer, self only)
      Body opt {name,phone,college,department|dept} -> 200 {student} |
      403 forbidden | 404

  Events (/api/events):
    GET /?search=&category=&college=&type=featured/upcoming/past/all&
        sort=upcoming|recent|popular&page=&limit=
      search regex on title/desc/college/organizer; category case-
      insensitive exact (All=no filter); college regex; type featured->
      featured true, upcoming date>=now, past date<now; sort upcoming
      date asc / recent createdAt desc / popular registeredCount desc.
      -> 200 {events(with spotsLeft,isFull), total, page, pages}
      Default sort upcoming, page1, limit12. Validation 400.
    GET /search?q= (q required) -> {events (max50 date asc), total}
    GET /category/:category (case-insensitive) -> {events max50, total}
    GET /categories -> {categories:[{name,count}]} (60s in-memory cache)
    POST /:id/register (Auth)
      Atomic findOneAndUpdate {_id, registeredCount<limit} $inc+1 ->
      create Registration(status Upcoming if future else Registered) ->
      rollback -1 on duplicate -> 201 {registration} | 404 no event |
      400 full | 409 already registered
    GET /:id -> 200 {event(withComputed)} | 404 | 400 invalid id

  Registrations (/api/registrations):
    POST / (optionalAuth: Bearer if present; else studentId in body)
      Body {eventId, studentId?} -> if token+body mismatch 403; if no id
      401. Atomic seat reserve, status Upcoming/Registered by date,
      populate eventId -> 201 {registration} | 404 | 400 full |
      409 duplicate
    GET /student/:studentId (optionalAuth, ownership if token)
      -> populate eventId sort registrationDate desc, bulk auto-mark
      Completed if event past -> 200 {registrations,total} | 403
    GET /:id -> populate eventId + studentId(-passwordHash) ->
      200 {registration} | 404
    DELETE /:id (Auth, owner only) -> delete + $inc -1 + clamp >=0 ->
      200 {message: Registration cancelled.} | 403 | 404

  Certificates (/api/certificates):
    GET /student/:studentId (optionalAuth, ownership if token)
      Find Completed registrations -> missing Certificates auto-created
      (Participation, url https://sympohub.io/certificates/{s}-{e}.pdf)
      insertMany ordered false ignore 11000 -> populate eventId sort
      issuedDate desc -> 200 {certificates,total} | 403

  System:
    GET / -> {message: SympoHub API running}
    GET /api/health -> {status: ok}
    * -> 404 {message: Route not found}
    Errors -> JSON {message} (+stack in development)

  Auth Header: Authorization: Bearer <JWT>
  Token: jwt.sign({id}, JWT_SECRET, {expiresIn:7d})

12. SECURITY & VALIDATION
--------------------------------------------------------------------------------
  - Passwords bcrypt-hashed (10 rounds), never returned (select
    -passwordHash, publicStudent helper).
  - JWT 7-day expiry, Bearer header, server 500 if JWT_SECRET missing.
  - express-validator on all inputs: email format+normalize, 10-digit
    phone, password min6, MongoId params, int page/limit, enum type/sort.
  - Ownership checks: PUT /students/:id self-only, DELETE registrations
    owner-only, GET student regs/certs enforce match when token present,
    POST registrations rejects token/body mismatch.
  - Duplicate guards: unique email, unique (student,event) registration
    + certificate, atomic $inc seat reserve with rollback on duplicate,
    oversell prevented via $expr registeredCount<limit.
  - CORS whitelist + credentials, 401 cleanup on frontend, XSS escape via
    .escape() on search/category/college params, centralized JSON errors.


13. KNOWN LIMITATIONS & FUTURE SCOPE
--------------------------------------------------------------------------------
  Current (v1.0.0):
    - Single Student role, no organizer/admin event creation UI (events
      via seed/DB directly).
    - Certificates are placeholder records with synthetic PDF URLs
      (https://sympohub.io/...), no real PDF generation or download.
    - No email/OTP, password reset, social login, or notifications.
    - No payment for paid events, no team management, no QR check-in.
    - Category counts cached 60s server-side; home counts client-side.
    - No automated tests or linter (lint script echoes placeholder).

    Admin/organizer dashboard (CRUD events, view registrations, issue
    certificates), real PDF certificates + download, email notifications,
    forgot-password, event image upload, payments (Razorpay/Stripe),
    team registrations, attendance QR, ratings/reviews, bookmarks,
    pagination server-side for Explore, unit/integration tests (Jest/
    Supertest), CI/CD + Docker + Atlas + Vercel/Render deploy.
